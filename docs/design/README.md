# 风标（Vane）主题规划

> 状态：0.1.0 尚未发布；2026-09-27 改名为风标，外观按单色工程风重画（§6） · 最近更新：2026-09-27
> 文档约定沿用 [Kite 设计文档](https://github.com/kite-plus/kite/blob/main/docs/design/README.md#文档约定)：正文中文，专有名词保留英文；`[待定]` 表示明确推迟决策。
> 主题名 `vane`，中文名风标；仓库 [`kite-plus/theme-vane`](https://github.com/kite-plus/theme-vane)，2026-09-26 建，公开；原名司南（`sinan`），2026-09-27 改名（§10 第 1 项）。

风标是 Kite 的第二套官方主题：一套文档站主题，也用来搭 www.kite.plus 官网。风标就是风向标，看风向、指方向：文档站本来就是给人指路的，Kite（风筝）又是乘风的。本文定下它的定位、页面、设置、外观和仓库，并列出 Kite 为它要补的契约和引擎能力。

---

## 1. 为什么是它

- **M5 要的就是它**。主题契约要等「用第一套主题的契约写一套风格完全不同的主题」之后才冻结（[theme-system.md §11.2](https://github.com/kite-plus/kite/blob/main/docs/design/theme-system.md#112-冻结时间表)）。博客主题用不到的东西——文档树、搜索、多语言、页面级的数据——正是文档站离不开的，写它最能把契约的缺陷逼出来。
- **官网用它搭**。官网要首页、文档和新闻（[官网规划 §2](https://github.com/kite-plus/website/blob/main/docs/design/README.md#2-页面)）。用 Kite 的官方主题、在 Kite 里写、由 Kite 构建和发布，官网本身就是整条链路的样板：写主题、装主题、试用、切换、发布，全都走真实产品。
- **生态打通**。主题放在自己的仓库里，打 tag 发版，用户在后台上传 zip 安装（Kite 已经支持），以后用 Git 地址安装；官网装的就是发布出去的版本。

## 2. 定位

面向产品文档、项目官网和知识库：一个首页，若干组有层级、有顺序的文档，外加新闻或博客。

不做的事：

- **博客主题**：默认主题「草木集」负责。
- **文档多版本切换**（v1、v2 各一套文档）：首版不做 `[待定]`。
- **在线编辑、评论、访问统计**：前两件由 Kite 后台和评论服务负责，统计属于站点，不属于主题。
- **依赖第三方资源**：和默认主题一样，不请求外部字体、脚本或样式。

## 3. 页面

| 页面 | 内容 | 现状（0.1.0） |
|---|---|---|
| 首页 | 一屏的定位和主按钮；特性或产品网格；可选的代码示例、截图和新闻列表 | 已做：标签条、标题、标语、按钮和一行可复制的命令、加框的截图、带编号的特性格子、最新三篇新闻；数据暂放主题设置（T8） |
| 文档页 | 左侧文档树，中间正文，右侧页内目录；上一页和下一页按文档顺序；「在 GitHub 上编辑」；最后更新时间 | 已做，文档树和顺序暂写在设置里（T1、T2）；标题下写着最后更新时间和阅读时间；差「在 GitHub 上编辑」（T7） |
| 文档目录页 | 一组文档的首页：说明加上这一组的目录 | 未做，等 T1、T2 |
| 新闻 | 文章列表、文章页、RSS | 已做 |
| 搜索 | 页头的搜索框，快捷键打开；按标题、小标题和正文搜，中文可用 | 单独用时按标题搜文档树和页头链接，`/` 或 `Ctrl K` 打开；站点装了官方搜索插件时，页头的搜索框改为打开插件的全文搜索（§10 第 3 项） |
| 语言切换 | 页头切换语言，没有对应译文时回到另一种语言的首页 | 随多语言（T5） |
| 404、归档、分类与标签 | 和默认主题一样齐全，否则过不了 `kite theme verify` | 已做，`kite theme verify` 通过 |

没有脚本时每个页面照样能用：窄屏的抽屉菜单靠一个复选框打开，页内目录在窄屏时是 `<details>`。脚本只负责锦上添花：深浅色按钮、搜索、代码块的标题栏和复制按钮、标题锚点、页内目录跟着滚动高亮。后台的整站预览不运行主题脚本，看到的就是没有脚本时的样子。

## 4. 主题设置

用 Kite 这次补齐的字段类型（`section`、`group`、`repeat`、`image`、`color`、`code`）声明。0.1.0 实际做成的是：

| 分组 | 设置 | 类型 |
|---|---|---|
| 品牌 | 标志、是否在标志旁显示站点标题、站点图标、强调色（四种推荐色，只用于链接下划线、焦点和搜索高亮）、深浅色默认值 | `image`、`boolean`、`image`、`color`、`select` |
| 导航 | 页头链接；页头按钮（文字、地址）；文档树：若干分组，每组一个标题加若干页面 | `repeat`；`string`、`url`；`repeat` 套 `repeat` |
| 公告栏 | 开关、文字、链接 | `boolean`，文字和链接用 `showIf` 跟着开关 |
| 首页 | 标签条（文字、标签、链接）、标题、标语、按钮、命令、配图和深色时的配图、特性标题、特性、是否显示最新新闻 | `string`、`url`、`text`、`repeat`、`image`、`boolean` |
| 文档 | 是否显示页内目录、最后更新时间、阅读时间 | `boolean` |
| 社交 | GitHub、X、Discord、邮件 | `group` |
| 页脚 | 几列链接，每列一个标题加若干链接；版权文字 | `repeat` 套 `repeat`、`string` |

和规划时的出入：公告栏没有用 `group`，放在 `section` 里的 `group` 只会多套一层框，`showIf` 照样用上了，`group` 由社交链接来用；页头按钮和首页的标签条也因此用平铺的键；0.1.0 原有的「插进 `<head>` 的 HTML」在 2026-09-27 去掉了，Kite 在「设置 → 站点」里有了站点自己的 head 和页脚代码，换主题也不丢，风标原样写出（§11 第 13 项）；「编辑链接」等 T7，「文档树展开几层」用不上，因为设置里的文档树只有两层。`theme.yaml` 本身就是英文，所以只有 `i18n/zh-CN.yaml`。「repeat 套 repeat」「用 `showIf` 跟着开关」「`group`」都在后台实际试过：安装、预览、填文档树、启用并保存都能走通。

## 5. 对 Kite 的依赖

对照现在的代码整理。它们大多也是 M5 冻结契约前本来就要定的事，这套主题负责把它们从「设计中」推到「实现并验证过」。

| # | Kite 要做的 | 现状 | 对主题的影响 |
|---|---|---|---|
| T1 | **文档的层级和顺序** | 内容类型只有内置的 post 和 page，page 的地址是平铺的 `/:slug`，没有目录层级，也没有手动顺序。内容模型属于站点而不属于主题（[theme-system.md §11.3](https://github.com/kite-plus/kite/blob/main/docs/design/theme-system.md#113-明确不做的东西)），所以应该由站点在 `kite.yaml` 里声明内容类型，Kite 开放注册表（[architecture.md](https://github.com/kite-plus/kite/blob/main/docs/design/architecture.md) 早就留了口子），路由支持按目录生成地址，排序支持 `weight` | **阻塞**文档页 |
| T2 | **文档树** | 模板拿不到按目录和 `weight` 组织的树。要和路线图里「菜单写进主题契约」（`.Site.Menus`）一起设计：手写的菜单来自 `kite.yaml`，文档树从内容生成，两者给模板的形状最好一样 | **阻塞**侧栏 |
| T3 | **按文档顺序的上一页、下一页** | 现在按发布时间，在同一类型里取前后篇 | 文档页底部导航 |
| T4 | **搜索索引** | 构建只输出页面、RSS 和 sitemap。要能输出一份 JSON 索引（输出格式或 completion hook），`kite serve` 也要给出同样的文件，`kite theme verify` 一起比对 | **阻塞**搜索 |
| T5 | **多语言** | 只支持一种语言。就是官网规划的 K1，那里 §6.1 列的八条同样适用；这次 Kite 已经把语言包格式（`i18n/<lang>.yaml`）定下来并用在了后台，模板里的 `T` 函数、地址前缀和译文关联还没做 | **阻塞**官网上线，不阻塞主题首版 |
| T6 | **Markdown 扩展** | 没有提示块、代码块标题、标签页。提示块建议用 GitHub 的 `> [!NOTE]` 写法，在 GitHub 上也能正常显示；标签页取决于 shortcode 的语法（[theme-system.md §14](https://github.com/kite-plus/kite/blob/main/docs/design/theme-system.md#14-开放问题-待定) 第 1 项） | 首版可以只做提示块 |
| T7 | **源文件路径** | RenderContext 没有给出页面的源文件路径，拼不出「在 GitHub 上编辑」的链接 | 编辑链接 |
| T8 | **首页的数据放在哪** | 首页的定位、特性、产品这些区块，放在主题设置里太挤，写死在模板里又没法改。建议让主题给布局声明字段：作者给首页选 `landing` 布局，后台就多出这几组字段，值写进首页的 front matter。这是对 `theme.yaml` 里 `layouts` 的扩展，要在冻结前评估 | 首页 |
| T9 | **`kite theme verify` 覆盖更多** | fixture 没有自定义类型、多语言和搜索索引 | 验证 |

## 6. 外观

2026-09-27 定为「单色工程风」。0.1.0 的第一版（当时叫司南）和 VitePress 的默认主题太像：左字右图的首页、胶囊按钮、浅灰底的特性卡片、同一个色相的靛蓝、浅灰的代码块，项目负责人不满意，要求先调研主流风格再定。调研把主流文档站归成六类（框架默认、单色工程、产品面板、编辑排版、品牌色块、经典技术），给出单色工程、纸本编辑、产品面板三个方向的概念稿，项目负责人选了单色工程风，参考 Vercel、Next.js、shadcn/ui、Tailwind CSS 和 Linear 的文档。调研在 lab 的 `research/docs-theme-styles-2026-09-27/`，选中的概念稿在 `design/theme-vane/2026-09-27/`，改之前的样子在 `design/theme-vane/2026-09-26-sinan/`。

- **和默认主题完全不同**，这是 M5 的要求：无衬线字体，信息密度更高，三栏布局（文档树、正文、页内目录），窄屏时文档树收进抽屉。
- **只用黑白灰**：用 1px 的细线分区，不用灰底色块；卡片描边而不填色。主按钮黑底白字、圆角 8px，次按钮描边。深色是纯黑 `#0a0a0a`。
- **强调色只做记号**：链接的下划线、键盘焦点和搜索结果的高亮，默认 Kite 蓝 `#3d65bd`。按钮、文档树的当前页、页内目录的当前节都保持黑白，所以用户换什么颜色都成立。
- **等宽小字当标签**：文档树的分组标题、面包屑、首页的区块标题、页脚的栏目标题，都是 11.5px 的等宽大写字母，字距 0.08em。
- **代码块**：描边、浅灰底、圆角 10px。有语言时顶部一条标题栏，写着语言名（shell 一类统一写「终端」）和复制按钮，语言取自 Kite 写在 `<pre>` 上的 `data-lang`（§11 第 12 项）；没有语言时复制按钮浮在右上角。
- **首页**：左对齐。标签条（黑底的版本号加一句话）、64px 的大标题和标语，黑色主按钮、描边次按钮和一行可复制的命令；下面是加框的产品截图，深色时可以换一张；再往下是带编号的细线格子，和按行排的新闻（等宽的日期、标题、摘要）。
- **细节**：正文最宽 45rem，文档树 272px，页内目录 224px；1280px 以下页内目录收到正文上方，1100px 以下收起页头的「/ 文档」和快捷键提示，960px 以下文档树和页头链接收进抽屉；正文 16px，中文行高 1.8；h1 36px、h2 22px，字重 600；引用画成带图标的描边提示框；代码配色写成 class，深浅两套各自达到 4.5:1。
- **深浅色**：和 explore 的前台一致。页头按钮在自动（跟随系统）、深色、浅色三种模式间循环，图标显示当前模式（显示器、月亮、太阳），提示写「深色模式 · 点击切换至浅色模式」。点击时新配色以按钮为圆心画圆铺满页面（View Transitions API，0.45 秒），新图标转着进来；颜色不变（例如系统本来就是深色时从自动切到深色）、读者要求减少动态效果或浏览器不支持时直接切换。切换那一刻暂停各元素自己的颜色过渡，整页在同一帧换色，不会有的先变、有的慢慢淡过去；动画没播完时再点一下也算数。浏览器顶栏的颜色（`theme-color`）跟着所选的配色。选择存在浏览器的 `localStorage`（键 `kite-theme`，和默认主题共用），别的标签页和从前进后退缓存恢复的页面会跟上；读者还没选时，页面按「深浅色默认值」设置显示。这段脚本内联在 `<head>` 里，首次绘制之前运行，所以保存过的选择不会闪一下别的配色，按钮也从第一帧起就在。
- **不做的**：不加载字体，不用渐变和插画，不用胶囊按钮和灰底卡片，这几样正是 VitePress 一类主题的标志。

## 7. 仓库

```
theme-vane/
├── theme.yaml
├── layouts/            # 模板；主题自己说的话都在 _partials/t.html
├── static/vane/       # vane.css、vane.js，发布在站点的 /vane/ 下
├── i18n/zh-CN.yaml     # 后台里主题的中文
├── screenshot.webp     # 1280×800，后台主题列表里用
├── example/            # 用这套主题的 Kite 站点，内容就是风标自己的使用文档
├── scripts/package.sh  # 打出后台能直接安装的 zip
├── LICENSE             # Apache-2.0
└── docs/design/        # 本文
```

- **和主程序分开**：风标的源码只在这个仓库里。Kite 主程序只内置默认主题，不打包、也不引用风标；风标也不引用 Kite 的源码，只依赖公开的主题契约，靠 `theme.yaml` 里的 `apiVersion` 和 `requires` 声明能配哪些版本的 Kite。
- **开发**：在 `example/` 里 `kite run`，主题通过 `example/themes/vane` 这个指向仓库根目录的符号链接接进去，改模板、样式、语言包保存即生效（Kite 原先不跟随这个链接，见 §11 第 1 项）。Kite 不会写穿符号链接指向的主题，在后台装同名主题也不会覆盖正在开发的文件。
- **CI**：`kite theme verify .`，再用 `kite build --verify` 构建 `example/`。
- **发版**：`scripts/package.sh` 打出 `dist/vane-<版本>.zip`（`theme.yaml` 在包里唯一的文件夹 `vane` 中，后台能直接安装），打 tag 并附上这个 zip。
- **官网怎么用它**：官网装的是发布出来的 zip：在后台上传安装或升级，文件落在官网的 `themes/vane/`，随发布一起提交。CI 构建不需要再去网上取主题，版本也看得见。官网发现主题的问题，回到这里修、发版，再在官网升级，不在官网仓库里直接改主题。

## 9. 与现有规划的关系

- **官网规划 §4 已改**：官网改用风标搭，风标做好之前沿用默认主题；默认主题的展示改为官网上的截图和示例站点。官网规划里 K3（按页面指定模板）和 K4（子路径）也已标为解决。
- **Kite 路线图 M5 一行**里的「写第二套风格完全不同的主题」就是风标。它推动的 T1–T9 进入 Kite 的排期，由 Kite 仓库记录实现和验收。Kite 的设计文档原先打算建一个 `kite-plus/themes` 仓库放所有官方主题，现在改成每套主题一个仓库、主程序只内置默认主题（[architecture.md §26](https://github.com/kite-plus/kite/blob/main/docs/design/architecture.md#26-github-organization-规划)）。

## 10. 待定问题

1. **名字**：已定。2026-09-26 先定为司南（`sinan`），仓库 `kite-plus/theme-sinan` 当天建成并公开；2026-09-27 外观改走单色工程风（§6），司南的古典气质和它对不上，改名为风标，主题名 `vane`，仓库随之改为 `kite-plus/theme-vane`。仓库名沿用「`theme-` + 名字」的写法，和 Halo 等项目的主题仓库一致。
2. **文档多版本**：建议首版不做。
3. **搜索**：已定。主题自带按标题的搜索，数据是页面里已有的文档树；正文搜索交给官方搜索插件 [`plugin-search`](https://github.com/kite-plus/plugin-search)，它在构建时写索引、在读者的浏览器里搜，静态和动态都能用。站点装了插件时（页面上有 `window.KiteSearch`），页头的搜索框加上 `data-kite-search`，直接打开插件的搜索，插件也就不再放自己的按钮。
4. **首页数据放在哪**（T8）：建议给布局声明字段；备选是全放主题设置，或者写死在模板里。0.1.0 暂放主题设置。
5. **设计稿**：已定（2026-09-27）。第一版没有出稿，直接做成了主题；项目负责人看过后要求换掉 VitePress 式的外观，调研后选了单色工程风（§6），按概念稿重画。
6. **许可证**：暂按建议用 Apache-2.0，和 Kite 一致（`LICENSE`、`theme.yaml`）。
7. **评论**：文档页要不要接 Kite Plus 评论（评论服务上线之后），默认关闭。

## 11. 写风标时发现的问题

写第二套主题就是为了把契约的缺陷逼出来。0.1.0 做下来发现这些，按该在哪边改分开：

| # | 问题 | 怎么办 |
|---|---|---|
| 1 | `kite serve` 监听 `themes/` 时不跟随符号链接：用链接接进来开发的主题，改了模板不生效；模板指纹还会扫到主题仓库里示例站点的索引，每次都当成主题改过 | **已在 Kite 修复**（cfd0700）：链接指向的主题在原处监听，只监听主题自己的目录；指纹只看 `theme.yaml`、layouts 和语言包 |
| 2 | 后台写新对象时按字母给键排序：文档树的分组写进 `kite.yaml` 是 `pages` 在前、`title` 在后，不是 `theme.yaml` 声明的顺序，手工读写时别扭 | Kite 待改：新写入的对象按 schema 的字段顺序排 |
| 3 | 嵌套列表在自定义器里偏挤：文档树「页面」一行的两个输入框各只有一百来像素，地址显示不全 | 后台待改：嵌套的列表改成上下排，或者让设置栏能拉宽 |
| 4 | 模板拿不到全站的页面：`.Site` 没有页面列表，文档树只能写在设置里，搜索只能从页面里已有的链接找标题 | T2、T4 |
| 5 | partial 只能输出 HTML：「这一页在不在文档树里」只能让 partial 输出 1 或空字符串，同一段查找在五个地方各写了一遍 | 契约待定：能返回值的 partial（像 Hugo 的 `return`），或者直接给模板文档树数据（T2） |
| 6 | `math.Add` 只收发浮点数：计数得从 `0.0` 开始，默认主题也这么绕 | 契约待定：加整数运算，或让 `math` 保留整数 |
| 7 | 集合函数只收 `[]any`：`.Pages` 是 `[]Page`，`coll.First 3 .Pages` 用不了，首页取三篇新闻只能 `range` 加下标 | 契约待改：集合函数接受任意切片 |
| 8 | 首页跟着新闻分页：`/page/2/` 也由首页模板画，文档站的首页得自己判断页码、改画新闻列表 | 契约待定：让主题声明首页不分页，或者把分页交给新闻列表 |
| 9 | 主题的脚本拿不到翻译：`t.html` 只在模板里能用，脚本要的「复制」「已复制」只能经 `<body>` 的 `data-*` 属性传过去 | 设计多语言（T5）的 `T` 函数时一起考虑脚本 |
| 10 | 全角标点后面的网址不会自动变成链接：`自动链接：https://…` 原样输出，默认主题下也一样 | Kite 待查，Markdown 层的问题 |
| 11 | 页面选了主题没有的布局：演示博客的关于页写着 `layout: links`，换成风标后退回页面自己的模板，照常显示 | 符合预期，不用改 |
| 12 | 代码块不写语言：高亮后的代码块只有 `<pre class="chroma">`，主题没法在标题栏里写出语言 | **已在 Kite 修复**（0be2f40）：高亮的代码块带上 `data-lang`；没写语言或 chroma 不认识的语言照旧，后者本来就有 `language-*` 类名 |
| 13 | 站点的 head 和页脚代码、作者、关键词和 noindex 有了 Kite 的站点设置（`.Site.HeadHTML` 等），主题自己的 `head_html` 就多余了，换主题还会丢 | 风标去掉 `head_html`，原样写出站点的这些值 |
