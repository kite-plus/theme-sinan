# 司南（Sinan）主题规划

> 状态：规划中，尚未开始实现 · 最近更新：2026-09-26
> 文档约定沿用 [Kite 设计文档](https://github.com/kite-plus/kite/blob/main/docs/design/README.md#文档约定)：正文中文，专有名词保留英文；`[待定]` 表示明确推迟决策。
> 主题名 `sinan`，中文名司南；仓库 `kite-plus/theme-sinan`，目前只在本地，等骨架能装能用之后再在 GitHub 上建（§10 第 1 项）。

司南是 Kite 的第二套官方主题：一套文档站主题，也用来搭 www.kite.plus 官网。名字取自司南，指南针的前身；「指南」本来就是给人指路的意思。本文定下它的定位、页面、设置、外观和仓库，并列出 Kite 为它要补的契约和引擎能力。

---

## 1. 为什么是它

- **M5 要的就是它**。主题契约要等「用第一套主题的契约写一套风格完全不同的主题」之后才冻结（[theme-system.md §11.2](https://github.com/kite-plus/kite/blob/main/docs/design/theme-system.md#112-冻结时间表)）。博客主题用不到的东西——文档树、搜索、多语言、页面级的数据——正是文档站离不开的，写它最能把契约的缺陷逼出来。
- **官网用它搭**。官网要首页、文档和新闻（[官网规划 §2](https://github.com/kite-plus/website/blob/main/docs/design/README.md#2-页面)）。用 Kite 的官方主题、在 Kite 里写、由 Kite 构建和发布，官网本身就是整条链路的样板：写主题、装主题、试用、切换、发布，全都走真实产品。
- **生态打通**。主题放在自己的仓库里，打 tag 发版，用户在后台上传 zip 安装（Kite 已经支持），以后用 Git 地址安装；官网装的就是发布出去的版本。

## 2. 定位

面向产品文档、项目官网和知识库：一个首页，若干组有层级、有顺序的文档，外加新闻或博客。

不做的事：

- **博客主题**：默认主题「草木集」负责。
- **文档多版本切换**（v1、v2 各一套文档）：首版不做 `[待定]`。
- **在线编辑、评论、访问统计**：前两件由 Kite 后台和评论服务负责，统计属于站点，不属于主题。
- **依赖第三方资源**：和默认主题一样，不请求外部字体、脚本或样式。

## 3. 页面

| 页面 | 内容 | 首版 |
|---|---|---|
| 首页 | 一屏的定位和主按钮；特性或产品网格；可选的代码示例、截图和新闻列表 | 做 |
| 文档页 | 左侧文档树，中间正文，右侧页内目录；上一页和下一页按文档顺序；「在 GitHub 上编辑」；最后更新时间 | 做 |
| 文档目录页 | 一组文档的首页：说明加上这一组的目录 | 做 |
| 新闻 | 文章列表、文章页、RSS | 做 |
| 搜索 | 页头的搜索框，快捷键打开；按标题、小标题和正文搜，中文可用 | 做 |
| 语言切换 | 页头切换语言，没有对应译文时回到另一种语言的首页 | 随多语言（T5） |
| 404、归档、分类与标签 | 和默认主题一样齐全，否则过不了 `kite theme verify` | 做 |

## 4. 主题设置

用 Kite 这次补齐的字段类型（`section`、`group`、`repeat`、`image`、`color`、`code`）声明，先按下面列，实现时再细化：

| 分组 | 设置 | 类型 |
|---|---|---|
| 品牌 | 标志、站点图标、强调色（给出几种推荐色）、深浅色默认值 | `image`、`image`、`color`、`select` |
| 导航 | 页头链接（文字、地址、是否外链） | `repeat` |
| 公告栏 | 开关、文字、链接 | `group`，其余字段用 `showIf` 跟着开关 |
| 文档 | 编辑链接的仓库地址与分支、是否显示最后更新时间、文档树默认展开几层 | `url`、`string`、`boolean`、`number` |
| 社交 | GitHub、X、Discord、邮件 | `group` |
| 页脚 | 几列链接，每列一个标题加若干链接；版权文字 | `repeat` 套 `repeat`、`string` |
| 高级 | 插进 `<head>` 的 HTML（给统计代码用） | `code`（`language: html`） |

中英两套文字放在 `i18n/zh-CN.yaml` 和 `i18n/en.yaml`，和默认主题一样由测试保证后台里没有漏翻的文字。页脚的「repeat 套 repeat」和「用 `showIf` 跟着开关」是默认主题没用到的写法，要在后台里实际试过。

## 5. 对 Kite 的依赖

对照现在的代码整理。它们大多也是 M5 冻结契约前本来就要定的事，这套主题负责把它们从「设计中」推到「实现并验证过」。

| # | Kite 要做的 | 现状 | 对主题的影响 |
|---|---|---|---|
| T1 | **文档的层级和顺序** | 内容类型只有内置的 post 和 page，page 的地址是平铺的 `/:slug`，没有目录层级，也没有手动顺序。内容模型属于站点而不属于主题（[theme-system.md §11.3](https://github.com/kite-plus/kite/blob/main/docs/design/theme-system.md#113-明确不做的东西)），所以应该由站点在 `kite.yaml` 里声明内容类型，Kite 开放注册表（[architecture.md](https://github.com/kite-plus/kite/blob/main/docs/design/architecture.md) 早就留了口子），路由支持按目录生成地址，排序支持 `weight` | **阻塞**文档页 |
| T2 | **文档树** | 模板拿不到按目录和 `weight` 组织的树。要和路线图里「菜单写进主题契约」（`.Site.Menus`）一起设计：手写的菜单来自 `kite.yaml`，文档树从内容生成，两者给模板的形状最好一样 | **阻塞**侧栏 |
| T3 | **按文档顺序的上一页、下一页** | 现在按发布时间，在同一类型里取前后篇 | 文档页底部导航 |
| T4 | **搜索索引** | 构建只输出页面、RSS 和 sitemap。要能输出一份 JSON 索引（输出格式或 completion hook），`kite serve` 也要给出同样的文件，`kite theme verify` 一起比对 | **阻塞**搜索 |
| T5 | **多语言** | 只支持一种语言。就是官网规划的 K1，那里 §6.1 列的八条同样适用；这次 Kite 已经把语言包格式（`i18n/<lang>.yaml`）定下来并用在了后台，模板里的 `T` 函数、地址前缀和译文关联还没做 | **阻塞**官网上线，不阻塞主题首版 |
| T6 | **Markdown 扩展** | 没有提示块、代码块标题、标签页。提示块建议用 GitHub 的 `> [!NOTE]` 写法，在 GitHub 上也能正常显示；标签页取决于 shortcode 的语法（[theme-system.md §14](https://github.com/kite-plus/kite/blob/main/docs/design/theme-system.md#14-开放问题-待定) 第 1 项） | 首版可以只做提示块 |
| T7 | **源文件路径** | RenderContext 没有给出页面的源文件路径，拼不出「在 GitHub 上编辑」的链接 | 编辑链接 |
| T8 | **首页的数据放在哪** | 首页的定位、特性、产品这些区块，放在主题设置里太挤，写死在模板里又没法改。建议让主题给布局声明字段：作者给首页选 `landing` 布局，后台就多出这几组字段，值写进首页的 front matter。这是对 `theme.yaml` 里 `layouts` 的扩展，要在冻结前评估 | 首页 |
| T9 | **`kite theme verify` 覆盖更多** | fixture 没有自定义类型、多语言和搜索索引 | 验证 |

## 6. 外观

- **和默认主题完全不同**，这是 M5 的要求：无衬线字体，信息密度更高，三栏布局（文档树、正文、页内目录），窄屏时文档树收进抽屉。
- **颜色**：以 Kite 的品牌蓝为强调色，调暗到链接在白底上的对比度达到 4.5:1（官网现在用 `#3d65bd`）；深浅两色，跟随系统，也能手动切换。
- **参考**：VitePress、Starlight、Docusaurus 的信息架构已经被大量文档站验证过，结构上可以借鉴，外观不照搬。
- **先出设计稿，再实现**：按 lab 的惯例存到 `lab/design/theme-sinan/<日期>/`，每改一版另起一个目录。设计稿由谁出 `[待定]`（§10 第 5 项）。

## 7. 仓库

```
theme-sinan/
├── theme.yaml
├── layouts/            # 模板
├── static/             # 样式表、搜索脚本、图标
├── i18n/               # en.yaml、zh-CN.yaml
├── screenshot.webp     # 1280×800，后台主题列表里用
├── example/            # 一个用这套主题的 Kite 站点，开发和截图用
└── docs/design/        # 本文
```

- **和主程序分开**：司南的源码只在这个仓库里。Kite 主程序只内置默认主题，不打包、也不引用司南；司南也不引用 Kite 的源码，只依赖公开的主题契约，靠 `theme.yaml` 里的 `apiVersion` 和 `requires` 声明能配哪些版本的 Kite。
- **开发**：在 `example/` 里 `kite run`，主题通过 `themes/` 下的符号链接接进去。Kite 不会写穿符号链接指向的主题，在后台装同名主题也不会覆盖正在开发的文件。
- **CI**：`kite theme verify .`，再用 `kite build --verify` 构建 `example/`。
- **发版**：打 tag，附上 zip 包（`theme.yaml` 在包里唯一的文件夹中，后台能直接安装）。
- **官网怎么用它**：官网装的是发布出来的 zip：在后台上传安装或升级，文件落在官网的 `themes/sinan/`，随发布一起提交。CI 构建不需要再去网上取主题，版本也看得见。官网发现主题的问题，回到这里修、发版，再在官网升级，不在官网仓库里直接改主题。

## 8. 里程碑

| 阶段 | 做什么 | 依赖 |
|---|---|---|
| **D0 规划** | 本文；定下 §10 的问题 | —— |
| **D1 设计稿** | 首页、文档页、窄屏、深色 | 不依赖 Kite，现在就能做 |
| **D2 骨架** | 用 Kite 现有的能力先做出来：文档暂用 page，文档树暂时写在设置里；通过 `kite theme verify`。这一步不等 T1，就能开始暴露契约问题 | —— |
| **D3 文档结构** | T1、T2、T3、T7，换成真正的文档类型和文档树 | Kite M5 |
| **D4 搜索与写作** | T4、T6 | Kite M5 |
| **D5 首页** | T8；做首页的 `landing` 布局 | Kite M5 |
| **D6 官网** | 官网切到这套主题：首页、文档、新闻；多语言随 T5 | 官网规划 W1–W3，T5 |
| **D7 1.0** | 契约冻结为 `kite/v1` 时发布主题 1.0，主题开发文档用它作例子 | M5 末 |

## 9. 与现有规划的关系

- **官网规划 §4 已改**：官网改用司南搭，司南做好之前沿用默认主题；默认主题的展示改为官网上的截图和示例站点。官网规划里 K3（按页面指定模板）和 K4（子路径）也已标为解决。
- **Kite 路线图 M5 一行**里的「写第二套风格完全不同的主题」就是司南。它推动的 T1–T9 进入 Kite 的排期，由 Kite 仓库记录实现和验收。Kite 的设计文档原先打算建一个 `kite-plus/themes` 仓库放所有官方主题，现在改成每套主题一个仓库、主程序只内置默认主题（[architecture.md §26](https://github.com/kite-plus/kite/blob/main/docs/design/architecture.md#26-github-organization-规划)）。

## 10. 待定问题

1. **名字**：已定（2026-09-26）。司南，主题名 `sinan`，仓库 `kite-plus/theme-sinan`，沿用「`theme-` + 名字」的写法，和 Halo 等项目的主题仓库一致；GitHub 仓库等骨架能装能用之后再建。
2. **文档多版本**：建议首版不做。
3. **搜索**：自己输出索引、主题自带前端搜索（建议，不依赖第三方，静态和动态都能用），还是接 Pagefind、Algolia 这类现成方案。
4. **首页数据放在哪**（T8）：建议给布局声明字段；备选是全放主题设置，或者写死在模板里。
5. **设计稿**：像默认主题那样由项目负责人提供，还是先出两三版方向稿再挑。
6. **许可证**：建议和 Kite 一样用 Apache-2.0。
7. **评论**：文档页要不要接 Kite Plus 评论（评论服务上线之后），默认关闭。
